# 추세 다이어트

체중과 섭취 칼로리만 기록하면, 체중 추세로 실제 소비 칼로리를 추정해 목표 칼로리를 매주 맞춰 주는 개인용 다이어트 기록 앱입니다.

- 기록은 먼저 이 기기의 브라우저(IndexedDB)에 저장됩니다. 로그인하면 계정(Supabase)에도 저장되어 다른 기기에서 이어 쓸 수 있습니다. 로그인하지 않아도 쓸 수 있습니다.
- 홈 화면에 설치해 앱처럼 쓸 수 있고, 오프라인에서도 동작합니다.
- 표시되는 수치는 추정치이며 의학적 조언이 아닙니다.

## 설계 원칙: 오래 이어 갈 수 있게

- **목표는 범위입니다.** 하루 목표 칼로리 위아래 100kcal까지는 목표 범위 안으로 봅니다.
- **하루가 아니라 한 주로 봅니다.** 하루를 넘겨도 한 주 평균이 범위 안이면 괜찮다고 알려 줍니다. 기록하지 않은 날과 아직 다 먹지 않은 오늘은 평균에서 뺍니다.
- **감량과 유지를 번갈아 갑니다.** 감량이 10주를 넘으면 주간 체크인에서 2주 유지 기간을 먼저 권하고, 추세 체중이 목표에 닿으면 유지로 넘어가기를 권합니다.
- **힘들면 속도를 늦춥니다.** 최근 섭취가 목표를 크게 넘으면 칼로리를 더 깎는 대신 감량 속도를 한 단계 늦추는 선택지를 먼저 냅니다.
- **기록을 끊김으로 재지 않습니다.** 연속 일수 대신 이번 주 7일 중 며칠을 기록했는지 보여 줍니다.

규칙은 `src/lib/sustain.ts`에 모여 있습니다.

## 기능

| 화면 | 하는 일 |
|---|---|
| 온보딩 | 키·체중·활동량과 감량 속도(천천히/보통/빠르게/유지)를 받아 하루 목표 범위를 계산합니다. |
| 오늘 | 먹은 양과 목표 범위, 자주 먹는 것 한 번에 기록, 식사 추가(한 칸에 `550` · `김치찌개 550` · `김치찌개`), 이번 주 요약, 체중 입력 |
| 추세 | 시작부터 목표까지의 진행, 실측 체중과 추세선, 기간별 변화, 하루 섭취와 목표 범위 |
| 주간 체크인 | 지난 한 주를 요약하고, 다음 한 주의 선택지(쉬어 가기 / 유지로 전환 / 속도 늦추기 / 새 추정치에 맞추기 / 그대로) 중 하나를 고릅니다. |
| 설정 | 계정 로그인과 동기화, 감량·유지 단계 전환, 프로필 수정, 백업 내보내기/가져오기, 초기화 |

## 계산 방식

- **추세 체중**: 지수이동평균입니다. 하루에 실측값과의 차이의 10%만 따라가고, 기록이 빠진 날은 간격만큼 보정합니다. (`src/lib/trend.ts`)
- **초기 소비 칼로리**: Mifflin-St Jeor 기초대사량 × 활동 계수
- **적응형 소비 칼로리**: 최근 21일 기준 `평균 섭취 − (추세 체중 변화 × 7700 ÷ 일수)`. 식사 기록 10일 이상, 체중 기록 5회 이상일 때만 계산하고, 새 값은 30%만 반영합니다. 식사 기록이 없는 날은 평균에서 제외합니다. (`src/lib/tdee.ts`)
- **목표 칼로리**: `소비 칼로리 − (주당 감량 kg × 7700 ÷ 7)`. 감량 속도는 주당 체중의 1% 이하, 목표는 여성 1,200 / 남성 1,500kcal 이상으로 제한합니다.

## 음식 검색 데이터

식품의약품안전처 「전국통합식품영양성분정보 표준데이터」(음식, 원재료성식품)를 공공데이터포털에서 받아 `public/food-db.json`으로 줄여 앱에 넣었습니다. 서버 없이 기기 안에서 검색하고, 오프라인에서도 동작합니다. 포장 가공식품 데이터는 건수가 많아 넣지 않았습니다.

```bash
node scripts/build-food-db.mjs   # 최신 데이터를 다시 받아 public/food-db.json 갱신
```

## 계정 동기화

- **저장소**: Supabase(Postgres). 테이블은 `public.records` 하나이고, 프로필·체중·식사·즐겨찾기·체크인을 `(user_id, kind, key)` 단위의 JSON으로 저장합니다. 스키마는 `supabase/migrations/`에 있습니다.
- **접근 제어**: 행 수준 보안(RLS)으로 로그인한 사용자가 자기 행만 읽고 쓸 수 있습니다. 앱에 들어가는 키는 공개용 키입니다.
- **방식**: 기기에 쓴 변경을 표시해 두었다가(`outbox`) 올리고, 마지막으로 받은 시각 이후의 서버 변경을 받아 옵니다. 삭제는 삭제 표시로 전달합니다. 같은 기록을 두 기기에서 고치면 서버에 나중에 도착한 쪽이 남습니다. (`src/sync/engine.ts`)
- **설정**: `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 환경변수가 없으면 계정 기능이 숨겨지고 기기 저장만으로 동작합니다. 로컬 개발은 `.env.local`에, 배포는 Vercel 환경변수에 넣습니다.

```bash
npx supabase db push --remote     # 스키마 변경 반영
npx supabase config push          # supabase/config.toml의 인증 설정 반영
```

## 개발

```bash
npm install
npm run dev      # 개발 서버
npm test         # 단위·화면 테스트
npm run build    # dist/ 에 빌드
```

`main` 브랜치에 푸시하면 Vercel이 빌드해서 https://trend-diet.vercel.app 에 배포합니다.

## 구조

```
src/
  lib/          순수 계산 함수 (추세, 소비 칼로리, 지속가능성 규칙, 계획, 날짜)
  index.css     디자인 시스템 (색·글꼴 토큰, 공통 구성 요소)
  storage.ts    저장 계층. 화면은 Dexie를 직접 쓰지 않습니다.
  sync/         계정 동기화 (엔진, Supabase 연결, 상태)
  store.ts      zustand 상태와 동작
  pages/        화면
  components/   화면에서 쓰는 조각
```

## 데이터 백업

로그인하지 않으면 데이터가 기기 한 대에만 있으므로, 설정 화면에서 주기적으로 백업 파일을 내보내세요. 브라우저 데이터를 지우거나 기기를 바꾸면 기록이 사라집니다. 로그인해 두면 다른 기기에서 로그인해 다시 불러올 수 있습니다.
